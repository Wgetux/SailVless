# SailVless

[English](README.md) | **Русский** | [简体中文](README.zh-CN.md)

Нативный прокси- и VPN-клиент для Sailfish OS. Умеет подписки и список серверов с пингом, подключается одной кнопкой.
Есть локальный SOCKS5/HTTP-прокси с паролем и системный VPN-режим (TUN) для всего трафика устройства.
Поддерживает VLESS (REALITY, Vision, XHTTP), VMess, Trojan, Shadowsocks, Hysteria2, TUIC и AmneziaWG.

Свободная программа под лицензией GNU GPL версии 3 или более поздней. Проверено на OnePlus 6T с Sailfish OS
5.1.0.11 (aarch64, ядро 4.9, Qt 5.6).

## Возможности

- **Протоколы:** VLESS (REALITY, Vision, XHTTP), VMess, Trojan, Shadowsocks (включая 2022) — ядро Xray;
  Hysteria2 (перескок портов, salamander) и TUIC — ядро sing-box. Ядро выбирается автоматически.
- **Транспорты:** TCP (в т.ч. HTTP-маскировка), WebSocket, gRPC, HTTPUpgrade, XHTTP; TLS / REALITY, uTLS-fingerprint,
  SNI, ALPN.
- **AmneziaWG** (и обычный WireGuard): конфиг `.conf` или ссылка AmneziaVPN `vpn://`. Параметры обфускации AWG
  1.0/1.5/2.0 (Jc, Jmin, Jmax, S1–S4, H1–H4, I1–I5) и AWG 3.1 (HeaderProtectionKey, ContentPaddingAddition,
  RandomTrailers, DisableCookies).
  - Работает в userspace на официальной библиотеке amneziawg-go и сетевом стеке gVisor, без своего TUN и без root.
  - `sailvless-awg` отдаёт туннель как SOCKS5, а Xray подключается к нему. Поэтому маршрутизация, локальный прокси,
    TUN-режим и проверка связи работают и для AWG.
  - Раздельные конфиги (AllowedIPs) учитываются.
- **Импорт:** ссылки `vless:// vmess:// trojan:// ss:// hysteria2:// hy2:// tuic:// vpn://` из буфера или вручную,
  полный JSON-конфиг Xray или sing-box, конфиги AmneziaWG/WireGuard (текстом или файлом).
- **Подписки:**
  - форматы: base64, список ссылок, Xray JSON (массив конфигов), sing-box JSON;
  - заголовки: `subscription-userinfo` (трафик и срок), `profile-title` (в т.ч. `base64:`), `profile-update-interval`,
    `support-url`, `announce`;
  - автообновление, в том числе через туннель, если панель заблокирована.
- **HWID для панелей Remnawave:**
  - `x-hwid` стабилен: это SHA-256 от machine-id и соли, сам machine-id не передаётся;
  - также передаются `x-device-os`, `x-ver-os`, `x-device-model` и свой User-Agent;
  - HWID можно посмотреть, сбросить или задать вручную;
  - при превышении лимита устройств выводится понятное сообщение.
- **Маршрутизация:** три режима:
  - всё через прокси;
  - обход локальной сети и страны: для `cn` — китайские сервисы и IP; для `ru` — российские сервисы, .ru/.su/.рф и IP;
    для других кодов — доменная зона страны и IP;
  - только свои правила.

  Плюс блокировка рекламы и правила по домену, суффиксу, подстроке, IP/подсети, geosite, geoip с действиями
  «прокси / напрямую / блок».
- **Правила для отдельного сервера:** проверяются раньше общих, например, чтобы при полном туннеле пускать некоторые
  сайты напрямую. Правила можно выгрузить в файл и загрузить обратно, а также выбрать сразу несколько и удалить.
- **DNS:** отдельно через прокси (DoH, TCP, UDP) и для прямых сайтов; в TUN-режиме DNS не утекает мимо туннеля.
- **Локальный прокси:** SOCKS5 и HTTP только на 127.0.0.1. Логин и пароль случайные и включены по умолчанию, порты
  можно задать или выбрать случайные. Открыть прокси в локальную сеть можно только явным переключателем
  с предупреждением.
- **TUN-режим:** весь трафик устройства идёт через туннель без настройки приложений. Режим переживает переключение
  Wi-Fi ↔ мобильная сеть, а при сбоях сеть возвращается в прямой режим, а не обрывается. В системе он виден как VPN
  «SailVless»: значок в строке состояния, переключатель в Настройки → VPN и в верхнем меню.
- **Интерфейс:** Silica, обложка с состоянием и кнопкой, пинг и «самый быстрый сервер», скорость и трафик,
  логи с копированием, уведомления о потере соединения и лимите устройств. Английский, русский и упрощённый китайский.

## Установка

Пакет ставится вручную (не из Harbour) от root:

```sh
devel-su pkcon install-local sailvless-<версия>.aarch64.rpm
```

После установки демон сразу запускается в сессии пользователя. Приложение — «SailVless» в списке приложений.
Не включайте одновременно другой VPN-клиент со своим туннелем (например, harbour-xhvpn).

## Как это устроено

```
QML/Silica UI ──session D-Bus──► sailvlessd (systemd --user, от пользователя)
                                   ├ профили, подписки, HWID, маршрутизация, гео-базы
                                   ├ режим прокси: сам запускает xray / sing-box (+ sailvless-awg для AmneziaWG)
                                   └──system D-Bus──► sailvless-tun-helper (root, запускается по требованию)
                                                       ├ ядро — от имени пользователя, только CAP_NET_ADMIN
                                                       └ sing-box TUN (свой конфиг, от root)
connman-vpnd ◄── плагин sailvless.so: показывает туннель как системный VPN (маршруты и DNS не трогает)
```

Данные хранятся в `~/.local/share/sailvless/` (каталог 0700). Ссылки подписок, UUID и пароли лежат только
в `secrets.json` (0600). В логах и интерфейсе URL подписки маскируется. Гео-базы — `~/.local/share/sailvless/geo`.

### TUN-режим

В ядре 4.9 нет правил маршрутизации по UID, поэтому трафик самого прокси-ядра отделяется меткой:

- сокеты ядра помечаются `SO_MARK`; правило `fwmark → main` стоит перед правилами туннеля,
  а `fwmark → unreachable` не даёт помеченному трафику провалиться в туннель;
- ответы возвращают метку через CONNMARK, `src_valid_mark=1` — чтобы строгий `rp_filter` на `wlan0` их принимал;
- локальная сеть исключена из туннеля, и телефон остаётся доступен из LAN. Но DNS-запросы к роутеру
  перенаправляются в туннель, иначе их видел бы провайдер. DNS к частным IPv6-адресам отклоняется: NAT для IPv6
  в ядре нет;
- IPv6 всегда перехватывается: по умолчанию отклоняется (приложения получают только IPv4-адреса),
  по желанию — проксируется;
- адреса серверов демон узнаёт до включения туннеля через системный DNS — это работает и при белых списках оператора;
- при смене сети перезапускается только ядро, туннель остаётся — окна для утечки нет.

Root-хелпер получает команды только от `defaultuser` (политика D-Bus) и сам строит конфиг TUN. Он ограничен
средствами systemd: `CapabilityBoundingSet`, `NoNewPrivileges`, `ProtectSystem=strict`, `ProtectHome=read-only`.
Всё, что хелпер меняет, снимается:
- при отключении;
- когда демон пропадает с шины;
- при падении хелпера (`ExecStopPost`);
- при следующем запуске.

При установке пакета перезапускается `connman-vpn.service`, и VPN другого клиента при этом отключится.

## Ограничения

- **Системный прокси Sailfish** (Настройки → Сеть) не поддерживает логин и пароль. С авторизацией используйте
  TUN-режим или указывайте прокси в приложении.
- **Нет раздельной маршрутизации по приложениям:** в ядре 4.9 нет правил по UID и nftables.
- **DNS-over-TLS** Xray не поддерживает — используйте DoH.
- **VLESS без TLS/REALITY** к публичным адресам Xray v26 запускать отказывается: это его политика, обойти нельзя.
- **`pinSHA256`** в ссылках Hysteria2 sing-box не поддерживает — параметр игнорируется с предупреждением в логе.
- **Маршрутизация для Hysteria2/TUIC** использует rule-set'ы SagerNet, которые sing-box скачивает сам; их целостность
  защищена только HTTPS. Hysteria2 и TUIC на реальных серверах не проверялись.
- **AmneziaWG:**
  - из ссылок `vpn://` берётся только AmneziaWG (OpenVPN/Cloak/XRay-контейнеры Amnezia не поддерживаются);
  - пинг для AWG-серверов не показывается (UDP); работает ли сервер, показывает проверка через туннель;
  - в раздельных конфигах сервер может пропускать только свой список сетей, тогда правила «через прокси»
    не добавят туда другие сайты.
- **Waydroid:** правила туннеля охватывают и пересылаемый трафик контейнеров, но форвардинг не включается
  и не проверялся.

## Сборка

Нужны Windows, Go 1.27+, Sailfish SDK 3.13+ (сборочный движок Docker, target `SailfishOS-5.1.0.11-aarch64`).

```powershell
.\build.ps1 -Cores          # один раз: Xray и sing-box из официальных исходников по тегам из cores\versions.lock
.\build.ps1 -Test -Rpm      # тесты, Go-бинарники (linux/arm64), RPM через sfdk -> out\rpm
.\deploy.ps1 -Rpm -RootDevice root@<телефон>   # установка по SSH-ключу root
```

Ядра собираются только из официальных репозиториев с закреплённым коммитом и `go mod verify`.
Заметки для разработки — в [CLAUDE.md](CLAUDE.md).

Переводы лежат в `ui/translations/*.json`. Сборка останавливается на любой непереведённой строке, поэтому для нового
текста нужна запись в `ru.json` и `zh_CN.json` (для множественного числа — ещё и в `en.json`). Новые переводы
приветствуются.

## Отладка

```sh
sailvlessd ctl status        # состояние, трафик
sailvlessd ctl logs 200      # логи демона, ядра и TUN-хелпера
sailvlessd ctl list          # серверы
sailvlessd ctl ping          # TCP-пинг всех серверов
sailvlessd ctl settings      # настройки (JSON); изменить: ctl settings '{"logLevel":"debug"}'
sailvlessd ctl rules <id>    # правила сервера; rules-export / rules-import — файлы
sailvlessd ctl hwid          # HWID и заголовки устройства
curl -x "$(sailvlessd ctl proxy-url)" https://ifconfig.me
```
